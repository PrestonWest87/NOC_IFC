# Tiered Alert & RCA Ticketing Escalation System

## Overview

24/7 Tiered Alert & RCA Ticketing Manager. Runs every 60 seconds via
`job_tiered_alert_escalation()` in `src/scheduler.py`. Determines priority,
applies SLA rules based on business hours, dispatches tickets, and pages oncall
personnel.

---

## Business Hours Logic

| Window | Definition | Behavior |
|--------|-----------|----------|
| **DAY SHIFT** | Monday–Friday 0600–2000 Central | Remedyforce tickets only. P1 immediate, P2–P5 delay 0–10 min (practically immediate since the scheduler loop is 1 min). |
| **AFTER HOURS** | Nights + Weekends | Full escalation: tickets + NOC notifications + oncall paging. Delays per SLA table. |

## Alert Processing Flow (per site)

1. **Skip** if site has no undispatched alerts.
2. **Site-level onpage mute** — skip if an escalation ticket was sent for this
   site within the last hour.
3. **Sort** undispatched alerts by `received_at` (oldest first).
4. **Root cause** — run `EnterpriseAIOpsEngine` (7-stage correlation) across all
   alerts at the site.
5. **Tier extraction** — pull priority from `raw_payload` fields:
   `Normalized_Alert_Level` → `Custom_Properties_Universal`.
6. **Cascade detection** — scan sibling alerts for a higher-priority tier. If
   found, cascade flag is set, wait time becomes 0, dispatch labels include
   `"CASCADE"`.
7. **Node flapping cooldown** — suppress repeated dispatches for the same node:
   P1 = 1 hour, P2–P5 = 5 hours.
8. **Wait time exceeded?** — if yes, dispatch.

## Dispatch Channels

| Channel | When Used | Description |
|---------|-----------|-------------|
| `REMEDYFORCE_TICKET_EMAIL` | Always (day + night) | SolarWinds Remedyforce ticket queue. **Required** — scheduler aborts if missing. |
| `NOC_NOTIFY_EMAIL` | After hours only | Informational notification to the NOC team. |
| `NOC_ONPAGE_EMAIL` | After hours, SWF devices | On-call pager for fiber hut / cabinet sites. |
| `ITNETWORK_ONPAGE_EMAIL` | After hours, non-SWF devices | On-call pager for all other device types. |

---

## SWF Device Detection

A site is classified as **SWF** when:

- `node_name` contains `"swf"` (case-insensitive), **OR**
- `loc_type` or `custom_properties` contains `"fiber hut"` or `"fiber cabinet"`.

SWF classification determines which oncall paging channel is used after hours.

---

## Cascade Detection

When a site has multiple active alerts, the system checks whether any sibling
alert carries a higher-priority tier. If so:

- The **cascade flag** is set.
- **Wait time** is forced to 0 (immediate dispatch).
- Dispatch subject and labels include `"CASCADE"` to indicate a multi-alert
  incident.

---

## Site Mute Logic

If a site received an escalation ticket within the **last hour**, all new alerts
at that site are suppressed. Suppressed alerts are marked as ticketed without
dispatching a new email. This prevents duplicate tickets during flapping or
rapid re-alerting.

---

## Ticket Format

**Subject:**

```
[DAY-SHIFT|AFTER-HOURS] [TICKET|SITE ESCALATION / CASCADE]: {TIER} Incident at {site}
```

**Body includes:**

- Priority and target SLA
- District
- RCA analysis output
- Device list with per-device status
- Trigger times

Body is generated by `generate_rca_ticket_text()` in `src/services.py`.
