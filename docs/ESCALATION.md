# Tiered Alert & RCA Ticketing Escalation System

## Overview

24/7 Tiered Alert & RCA Ticketing Manager. Runs every 60 seconds via
`job_tiered_alert_escalation()` in `src/scheduler.py`. Determines priority,
applies SLA rules based on business hours, dispatches tickets, and pages oncall
personnel.

---

## Business Hours Logic

| Window | Definition | Behavior |
|--------|-----------|----------|
| **DAY SHIFT** | Monday–Friday 0600–2000 Central | Remedyforce tickets only. P1 immediate, P2–P5 delay 0–10 min (practically immediate since the scheduler loop is 1 min). |
| **AFTER HOURS** | Nights + Weekends | Full escalation: tickets + NOC notifications + oncall paging. Delays per SLA table. |

## Alert Processing Flow (per site)

1. Load unresolved alerts received in the last 12 hours and group them by site.
2. Keep automatic ticket eligibility separate from page eligibility. A successfully
   ticketed P1 can still retry a page that failed; a successful page is not repeated
   during the same unresolved node incident.
3. Extract priority from `raw_payload` fields:
   `Normalized_Alert_Level` → `Custom_Properties_Universal`.
4. Apply node cooldown to the same node only: P1 = 1 hour, P2–P5 = 5 hours.
   A suppressed node remains pending and does not consume unrelated site alerts.
5. Detect a higher-priority sibling tier. A cascade forces its wait to 0 and labels
   the site dispatch as a cascade.
6. Apply the one-hour after-hours site cooldown to routine site tickets/pages. P1
   tickets bypass the site cooldown; an eligible P1 page also bypasses it when the
   active node incident has not already been paged.
7. Send one site-level ticket for the eligible site cluster. Mark alerts ticketed
   only after the ticket email succeeds. Record page delivery independently on the
   active node incident.

## Dispatch Channels

| Channel | When Used | Description |
|---------|-----------|-------------|
| `REMEDYFORCE_TICKET_EMAIL` | Always (day + night) | SolarWinds Remedyforce ticket queue. **Required** — scheduler aborts if missing. |
| `NOC_NOTIFY_EMAIL` | After hours only | Informational notification to the NOC team. |
| `NOC_ONPAGE_EMAIL` | After hours, SWF devices | On-call pager for fiber hut / cabinet sites. |
| `ITNETWORK_ONPAGE_EMAIL` | After hours, non-SWF devices | On-call pager for all other device types. |

---

## SWF Device Detection

A site is classified as **SWF** when:

- `node_name` contains `"swf"` (case-insensitive), **OR**
- `loc_type` or `custom_properties` contains `"fiber hut"` or `"fiber cabinet"`.

SWF classification determines which oncall paging channel is used after hours.

---

## Cascade Detection

When a site has multiple active alerts, the system checks whether any sibling
alert carries a higher-priority tier. If so:

- The **cascade flag** is set.
- **Wait time** is forced to 0 (immediate dispatch).
- Dispatch subject and labels include `"CASCADE"` to indicate a multi-alert
  incident.

---

## Site Mute Logic

After a successful page, `MonitoredLocation.last_escalation_ticket` anchors a
one-hour after-hours site cooldown. Routine new site alerts remain unresolved and
un-ticketed during that window; they are eligible for the next site-level ticket
after cooldown. P1-high and P1-low incidents can create a new site-level ticket
during the cooldown. They can also page during the cooldown if that active node
incident has not already been paged. Successful per-node page delivery is recorded
in `SolarWindsAlert.onpage_sent_at`; a resolution ends that active incident's page
deduplication scope.

Maintenance status is not an escalation filter. Maintenance does not prevent alert
ingestion, site ticket creation, or an otherwise eligible page.

---

## Ticket Format

**Subject:**

```
[DAY-SHIFT|AFTER-HOURS] [TICKET|SITE ESCALATION / CASCADE]: {TIER} Incident at {site}
```

**Body includes:**

- Priority and target SLA
- District
- RCA analysis output
- Device list with per-device status
- Trigger times

Body is generated by `generate_rca_ticket_text()` in `src/services.py`.
