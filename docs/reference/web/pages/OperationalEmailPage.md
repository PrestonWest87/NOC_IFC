# Page: Operational Email

**Source:** `web/src/pages/OperationalEmailPage.tsx`
**Route:** `#/operational-email`
**Permission:** `Operational Email`

The page provides Compose, Scheduled, Sent / History, and administrator-only Template Defaults and Signatures panels. The page grant authorizes all ordinary page functions; shared defaults and signature administration are additionally restricted to administrators. Per-message recipients, subject, and body remain editable for page users except the live Morning Report and the company-grouped Fiber Maintenance subject/message previews.

Fiber Outage ONPAGE provides optional free-text Rcount, Maps URL, and Closest Hand Hole inputs and includes supplied values in its message. Fiber Outage Follow-up and Resolution do not show Current status or Current service status fields.

Fiber outage and grouped Fiber Maintenance follow-up BCC copies are rendered per company. A contact gets circuit/network-order fields only for circuits mapped to that Fiber-contact company; other or unlisted BCC contacts receive the rest of the message with those fields blank. BCC-only copies use the active Global From address in To while keeping the BCC recipients hidden. This applies to immediate, scheduled, ONPAGE, and linked outage or maintenance messages.

The searchable Network Orders/Circuit IDs selector includes only the immediate associations of explicitly selected circuits; it does not follow associations of auto-included circuits. Operators can unselect direct associations that are not affected by a particular message; free-text Network Orders/Circuit IDs entry and configured-ID paste are retained.

The eleven templates include Maintenance Notification, Fiber Maintenance Notification, Maintenance Start, Maintenance Complete, Outage — Request Technician Dispatch, Fiber Outage, Fiber Outage ONPAGE, Fiber Outage Follow-up, Fiber Outage Resolution, After-Hours ONPAGE, and Morning Report. Fiber Outage without selected circuits and single-message follow-up To defaults use the active Global From address. Selected-circuit Fiber Outage and Fiber Maintenance route mapped Fiber contacts to To per company and Global From to Cc. The searchable Fiber-contact BCC selector appears only on Fiber Outage and Fiber Outage Resolution; mapped To contacts are not copied automatically to BCC, and manually entered BCC plus inherited source BCC remains supported. Fiber Maintenance requires selected configured circuits and mapped Fiber contacts; it creates one message per company with only that company's circuits/A-Z details and company contacts in To. Each circuit ID is displayed beside its A/Z locations on its own line; linked Maintenance Start/Complete messages carry the grouped details forward. An administrator-configured default Cc can be added, and the sender can edit Cc for each message. Scheduled sends use the same split. Grouped Fiber Maintenance and Fiber Outage sources appear once in their selectors; linked messages fan out once per company with a successful original delivery and retain that company's recipients/circuit subset. Fiber contact names/phones are not autofilled into message text. The shared-template subject/message previews for company-grouped messages are read-only and each message is rendered separately. After-Hours ONPAGE and Fiber Outage ONPAGE are the only templates that show ONPAGE contacts. Fiber Outage ONPAGE sends those contacts to To and the Global From address on Cc, without automatic Fiber BCC from Network Orders/Circuit IDs. Fiber follow-up and resolution messages omit ONPAGE To and inherit Location, Network Orders/Circuit IDs, and BCC from either initial Fiber template. The Network Orders/Circuit IDs multi-picker is searchable; pasting configured IDs selects matching records and fills company-specific To recipients and A/Z fields for Fiber messages, while Fiber Outage Location remains operator-entered. Fiber Maintenance offers MOP Type choices (Demand, Standard, Emergency) and Expected impact; Maintenance Notification has the Department performing the change selector and one optional Expected impact field for operational and departmental effects.

Maintenance Start selects a successfully sent Maintenance Notification or Fiber Maintenance Notification and inherits the source fields and recipients. Maintenance Complete can close out the same source messages, carries Fiber Network Orders/Circuit IDs and paired A/Z locations into its read-only field, includes Fiber details, and inherits source BCC; grouped Fiber Maintenance sources create one Start/Complete message per successfully delivered company. Both templates offer administrator-configured, sender-editable default Cc. Maintenance Notification combines operational and departmental effects in one Expected impact field, carried into linked Start/Complete messages. Operational Email event timestamps use calendar controls. Planned maintenance windows in sent messages use `MM/DD/YY HH:MM AM/PM` and the active CST/CDT label; other date/time fields use that format and append a timezone suffix where their template includes one. IDs in those fields are bolded in the HTML alternative while plain text remains intact. Timezone fields are automatic and hidden from the compose form. Messages are sent as plain-text and preformatted HTML alternatives, preserving line breaks, and subjects do not receive the automatic NOC FUSION prefix.

Morning Report displays the latest Global Dashboard shift analysis and refreshes it before delivery; it omits report date/window/title and executive-summary wrapping. The optional selected signature is appended to the message and snapshotted with sent or scheduled content. One-time sends accept a Central date/time; daily and weekly schedules use `America/Chicago`. Message snapshots, recipient lists, signatures, and attachment bytes are persisted in SQLite and delivered by the worker. The sender is displayed from the active global sender profile and cannot be overridden by the page; delivery history records whether existing SMTP or Gmail was used.

React Query loads templates, signatures, and conditionally loads maintenance/fiber source records, schedule, and history data. 401/403 messages come from the shared API client; send, schedule, cancellation, template-save, and signature-management results use accessible status/alert announcements.
